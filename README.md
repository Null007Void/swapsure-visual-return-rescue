# SwapSure — visual return rescue

SwapSure is a small local web application that turns a disappointing online return into a rescue
attempt: instead of posting a garment back, the shopper sees what an eligible alternative would look
like on their own photo, then chooses between the exchange and the ordinary refund.

This repository is the complete, runnable product: a Python 3.13 web application, an offline
demonstration mode, and an optional live integration with Perfect Corp's YouCam virtual try-on API.

## What is real and what is simulated

| Part | Status |
| --- | --- |
| Merchant, order, stock, price and exchange | **Simulated.** A synthetic sample merchant, sample orders and sample catalogue. No real shop is connected. |
| Previews in MOCK mode | **Simulated locally.** Placeholder images drawn on this machine. Zero provider calls, zero units. |
| Previews in LIVE mode | **Real provider work.** The shopper's photo and one garment reference are sent to Perfect Corp and a paid task is created. |
| Refund | Recorded as a handoff to the merchant's return portal. No money moves here. |

Nothing in this project guarantees a fit, a completed exchange, or that every garment in the sample
catalogue will be accepted by the provider. The bundled references are synthetic and have not been
live-qualified image by image; see `docs/CATALOG-PROVIDER-CATEGORIES.md`.

## Quick start on Windows, Python 3.13, no credentials

```powershell
git clone <this repository> SwapSure
cd SwapSure
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install "Pillow>=10,<13"

$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe src\ui\server.py --port 8000 --preview-mode MOCK --data-dir data
```

Open <http://127.0.0.1:8000/>. Pick **Women's** or **Men's**, click a garment card, opt in, give image
consent, upload a PNG (the upload control accepts **PNG only**) of at least 512×384, then press **Generate preview**. In MOCK mode this costs
nothing and produces local placeholders. No key, no network, no account.

Install the test runner (development only; the product itself needs only Pillow) and run the suite:

```powershell
.\.venv\Scripts\python.exe -m pip install pytest jsonschema
$env:PYTHONPATH = "src;tests"
.\.venv\Scripts\python.exe -m pytest -q
```

## The journey the product implements

1. **Choose a collection** — Women's or Men's. The application never infers it from a photo.
2. **Click a garment card** — that SKU is bound to the session on the server. The page then shows the
   selected garment with its thumbnail, name, size, price and category, one **Generate preview**
   button carrying the cost, and **Change garment**.
3. **Opt in and give image consent**, then upload your own photo. Consent is recorded separately from
   the rescue; declining it keeps the ordinary return available.
4. **Generate** — one explicit action, priced before it is pressed. Nothing is generated by browsing,
   by choosing, by uploading or by refreshing.
5. **See the result** and decide: choose the alternative for a quote, or continue the refund.
   **Try something else on** keeps the photo and consent and reopens garment selection; **Change
   photo** invalidates the previous photo's consent and results while preserving a still-eligible
   garment choice.

## YouCam integration, honestly described

* One garment per task. The provider endpoint takes a *single* reference image; this product never
  presents a single-garment preview as a multi-item outfit.
* Each garment carries **its own verified provider category** (`full_body`, `upper_body`,
  `lower_body`, `outer`) resolved on the server from the bundled catalogue — a dress and a men's
  jacket can be previewed in one session without restarting, and a category supplied by the browser
  is never accepted.
* A garment with no verified category is refused **before** any unit is reserved or any image is
  transmitted.
* Provider "success" is not taken as delivery: the result bytes are fetched through a bounded,
  allow-listed path and decoded before an image is offered. Undecodable bytes produce a clear
  refusal, not a broken picture.

## Consent, deletion and retention

* Consent is explicit, versioned and revocable. Revoking it stops further dispatch, discards
  in-flight work, deletes the local photo and cached results, and moves the return to the refund.
* **Delete local previews** removes what this server holds — your photo and any cached result bytes —
  and says so. It does **not** delete anything the provider already received. Provider-side copies
  are governed by Perfect Corp's own retention terms; this project makes no claim about them and
  cannot verify them.
* Result images expire. When one expires the page says so, drops the image element entirely, and
  keeps the refund and the next choices visible.

## Usage limits

LIVE mode is capped in the launcher, not in the UI: a per-preview cost of 2 provider units, a session
cap and an authorization-wide cap, all enforced by a local ledger that records every reservation with
the operation identity it belongs to. The ledger is never reset by a new build, so upgrading does not
grant a fresh allowance. Repeating the same photo-and-garment pair is refused instead of charged.

## Running LIVE (optional, costs money)

You need your own YouCam API key and an authorization reference you choose. Enter the key **at the
prompt** — never on a command line, never in a file:

```powershell
$env:PYTHONPATH = "src"
$env:SWAPSURE_LIVE_AUTHORIZATION_REF = "your-own-reference"
$env:SWAPSURE_LIVE_ALLOWED_HOSTS      = "yce-api-01.makeupar.com,yce-us.s3-accelerate.amazonaws.com"
$env:SWAPSURE_LIVE_UNIT_COST          = "2"
$env:SWAPSURE_LIVE_UNIT_CAP           = "4"
$env:SWAPSURE_LIVE_SESSION_UNIT_CAP   = "2"
$sec = Read-Host "YouCam API key" -AsSecureString
$bstr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($sec)
$env:YOUCAM_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($bstr)
[Runtime.InteropServices.Marshal]::ZeroFreeBSTR($bstr)
try   { .\.venv\Scripts\python.exe src\ui\server.py --port 8000 --preview-mode LIVE --data-dir data }
finally { Remove-Item Env:YOUCAM_API_KEY, Env:SWAPSURE_LIVE_AUTHORIZATION_REF -ErrorAction SilentlyContinue }
```

While the server runs, the key lives in that PowerShell process's environment, which anything running
as your user can read; the `finally` block removes it when the server exits. Set `SWAPSURE_LIVE_LEDGER`
to keep the spending ledger somewhere explicit.
